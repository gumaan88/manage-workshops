# تشغيل بيانات Seed

`digital_transformation_workshop.seed.json` هو المصدر الدلالي الكامل للورشة المرجعية، و`scenario_library.seed.json` يضيف خمس حالات احتياطية للمجموعات. `demo_completed_run.seed.json` ملف اختياري ينشئ نسخة محاكاة مكتملة لاختبار التقارير والشهادات دون تغيير الورشة المجدولة. `database/0002_seed_reference.sql` يثبت نسخة علائقية قابلة للفحص على SQLite/D1.

في التطبيق النهائي يجب أن ينفذ `npm run db:seed:local` سكربت TypeScript idempotent يقوم بالآتي:

1. يقرأ متغيرات `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `SEED_FACILITATOR_EMAIL`, `SEED_FACILITATOR_PASSWORD`, وبيانات مشارك تجريبي إن وُجدت.
2. ينشئ الحسابات عبر Better Auth API/adapter المعتمد حتى تكون hashes والجلسات متوافقة مع النسخة المثبتة؛ لا يكتب password hash ثابتًا من هذه الحزمة.
3. يطبق الكيانات المرجعية باستخدام مفاتيح ثابتة أو upsert آمن.
4. ينشئ 22 سجل مستخدم اصطناعيًا بأسماء «ممثل تجريبي - اسم المنظمة» دون حسابات دخول، ويربط كلًا بمنظمته ومجموعته.
5. ينشئ حساب مشارك تجريبي واحدًا من متغيرات البيئة، ويربطه بإحدى المنظمات، أو يحول أحد السجلات الاصطناعية إلى الحساب الفعلي.
6. يقفل إصدارات الأنشطة بعد إنشائها ويربط `current_version_id` وبنود الأجندة.
7. يطبع ملخص counts فقط، ولا يطبع كلمات المرور.

ينفذ `npm run db:seed:demo-run` ملف المحاكاة الاختياري، ويجب أن يتوقف إذا كانت البيئة `production`.

يجب أن يكون تشغيل Seed مرتين بلا تكرار. في الإنتاج لا يُشغل Seed التجريبي؛ يستخدم أمر `bootstrap-admin` مستقل لإنشاء أول مالك من أسرار البيئة، ثم تُنشأ البيانات الحقيقية من الواجهة أو استيراد معتمد.
